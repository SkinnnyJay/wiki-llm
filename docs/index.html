llm-wiki

A Claude Code plugin that scaffolds a vault — raw/, wiki/, schema, ingest, viewers, and vault git — so your knowledge can compound as markdown instead of disappearing into chat.

Inspiration

If I have seen further it is by standing on the shoulders of Giants.

— Isaac Newton, letter to Robert Hooke, 1675
(echoing Bernard of Chartres, nanos gigantum humeris insidentes)

The LLM Wiki idea — a persistent, interlinked wiki the model maintains between immutable raw sources and a schema that disciplines ingest, query, and lint — was articulated as a copy-paste pattern for any coding agent in Andrej Karpathy’s gist llm-wiki.md (April 2026).

That document is intentionally abstract: “The exact directory structure, the schema conventions … will depend on your domain … Your LLM can figure out the rest.” wiki-llm is one concrete, opinionated implementation for Claude Code, with a Python CLI, plugin manifest, skills, and slash commands.

Why this repo

Goal

Ship a reusable plugin so you do not have to reinvent vault layout, ingest adapters, static graph viewer, optional vault-scoped Git, or ingestion-security hooks. You curate sources and questions; the agent does the filing, cross-links, and maintenance described in llm-wiki/CLAUDE.md and the bundled skills.

  • Ingest (file, URL, Hacker News, optional Firecrawl / Perplexity / …)
  • build-site → wiki/.og/ viewer + wikilinks graph data
  • Optional lifecycle-tagged Git inside the vault
  • Heuristic prompt-injection scan + wiki-ingest review path
Install

Setup by environment

Pick the row that matches your toolchain. The pattern (raw → wiki → schema) is the same; only the wiring differs.

Claude Code

First-class path: add this repo as a plugin marketplace, then install the plugin (no clone required for daily use).

/plugin marketplace add https://github.com/wiki-llm/wiki-llm
/plugin install llm-wiki@llm-wiki-local

Update: /plugin marketplace update · Reload: /reload-plugins · Docs: Discover plugins

Cursor

Cursor plugins bundle rules, skills, MCP, hooks, and more. This repo includes .cursor-plugin/plugin.json (for Marketplace packaging) and rules/llm-wiki.mdc — the same rule file is linked under .cursor/rules/ so opening the clone just works.

See AGENTS.md for the full Claude vs Cursor vs Codex matrix. Optional: Claude Code with plugins enabled alongside Cursor, then use the marketplace commands in the Claude Code flow your setup exposes.

OpenAI Codex & others

Codex loads root AGENTS.md automatically (discovery). Same CLI, commands/ prompts, and skills. Per-vault rules after llm-wiki setup live in llm-wiki/CLAUDE.md; mirror key points into your project’s AGENTS.md if your tool only reads the repo root.

For Pi / OpenCode–style setups: same ideas as in the gist; use bin/llm-wiki from a terminal for deterministic ingest and build-site regardless of which model edits the wiki.

Obsidian

Optional: open llm-wiki/wiki/ in Obsidian as the reader/IDE while the agent writes — same idea as in the gist. The plugin remains the automation layer.

Developers

Clone & develop the plugin

Use when you are modifying the plugin source or need a local path to the repo.

git clone https://github.com/wiki-llm/wiki-llm.git
cd wiki-llm
claude --plugin-dir .

After edits: /reload-plugins · Validate: claude plugin validate or /plugin validate

CLI without marketplace

python3 scripts/llm_wiki.py --help
Vault

How to use (after setup)

  1. Scaffold a vault in your project root.

    llm-wiki setup --root .

  2. Configure (optional).

    llm-wiki configure -i

  3. Ingest, then merge into wiki/ via skills.

    llm-wiki ingest file ./notes.md --out clips/notes.md
llm-wiki ingest url https://example.com --out clips/example.md

    In chat: /llm-wiki:ingest and the wiki-ingest skill.

  4. Build the static viewer.

    llm-wiki build-site
cd llm-wiki/wiki/.og && python3 -m http.server 8765

    Open http://127.0.0.1:8765/ (serve over HTTP, not file://).
