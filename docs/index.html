Claude Code Plugin

llm-wiki

Turn scattered source material into a maintained wiki your agent can keep building on.

Scaffold raw/, wiki/, and schema-backed workflows so source captures stay immutable, curated pages stay linkable, and the command flow stays simple enough to reuse across repos.

Install once 
/plugin marketplace add https://github.com/wiki-llm/wiki-llm
/plugin install llm-wiki@llm-wiki-local

Then try one clean first workflow

1. Setup the vault 
llm-wiki setup --root .
2. Ingest one source 
llm-wiki ingest url https://example.com --out clips/example.md
3. Build the viewer 
llm-wiki build-site

That path gets you from raw capture to a browseable graph-backed wiki without making the landing page feel like full documentation.

Details

How the landing pieces map to the actual repo

01

Vault Structure

The vault keeps raw inputs separate from curated knowledge. That lets you preserve the source of truth, revise derived notes safely, and keep schema-driven rules nearby. 

llm-wiki/
  raw/        # immutable source captures
  wiki/       # curated markdown pages
  .schema/    # validation and structure rules
  outputs/    # optional reports and generated artifacts
  • raw/ protects the original material.
  • wiki/ holds maintained markdown the agent can improve over time.
  • .schema/ keeps ingest, query, and lint behavior disciplined.
  • Generated viewer artifacts can live alongside the vault without replacing the markdown source.
02

Ingest Pipeline

The pipeline is designed so new sources enter as recorded inputs first, then move through review and curation into the wiki layer.

Source
file, URL, HN, optional connectors
raw/
captured without rewriting history
wiki/
curated markdown and linked notes
llm-wiki ingest file ./notes.md --out clips/notes.md
llm-wiki ingest url https://example.com --out clips/example.md
  • Files, URLs, and Hacker News threads can all enter the same workflow.
  • Optional connectors can extend capture without changing the vault model.
  • The review path helps keep prompt-injected or low-trust material from silently becoming wiki truth.
03

Static Viewer

After ingest and curation, build-site turns the wiki into a static reader with graph data, linked-page browsing, and an app-like interface that is easy to host or inspect locally. 

llm-wiki build-site
cd llm-wiki/wiki/.og && python3 -m http.server 8765

Serve the viewer over HTTP, not file://, so graph assets and wiki data load predictably.

04

Skills & Commands

The repo bundles the operational layer too: CLI commands, slash-command prompts, and agent skills that describe how the wiki should be maintained. The goal is to show a small, memorable command surface first, then let deeper docs carry the rest.

Try this first

A minimal command path that demonstrates the whole loop.

Install /plugin install llm-wiki@llm-wiki-local
Setup llm-wiki setup --root .
Ingest llm-wiki ingest url https://example.com --out clips/example.md
Build llm-wiki build-site

Core commands

  • setup scaffolds the vault layout.
  • ingest records new files, URLs, and other sources into raw/.
  • build-site generates the static reader and graph view.

Keep it healthy

  • configure -i helps tune the vault interactively.
  • raw validate and related raw commands help finish captures cleanly.
  • wiki-ingest, wiki-query, and other skills keep the workflow in chat.

Also works with: manual clone for local plugin work, direct CLI usage via bin/llm-wiki or python3 scripts/llm_wiki.py, Cursor and Codex through AGENTS.md, and Obsidian as an optional reader for llm-wiki/wiki/.

Commands, workflows, and ethos live in README, WORKFLOWS.md, ETHOS.md, and the repo skills.

Lineage: the reusable LLM wiki pattern was popularized in Karpathy's llm-wiki.md gist. This repo is a concrete plugin implementation for Claude Code and adjacent agent tooling.
